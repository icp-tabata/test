# screen-event-reviewer モードC（設計変更後レビュー）詳細規則

`screen-event-reviewer` がモードC（設計変更後レビュー）として呼び出された場合にのみ適用される規則。呼び出し元から本ファイルのパスが提示されたら、着手前に必ず Read すること。本体（`screen-event-reviewer.md`）のモードA・Bの内容とは独立しており、モードA・Bの呼び出しではこのファイルは不要（Readしない）。

## 検査J: 変更内容一覧との整合検証

作成者（designer）の「変更内容一覧」は照合対象であって根拠ではない。呼び出し元が提示した「変更内容の指示」の全項目について、自分で現在の設計書と突き合わせ、以下を検証する。

- 指示された変更が、実際に該当箇所へ正しく反映されているか
- 未決事項を解消した箇所が、呼び出し元提示の新しい出典で実際に裏付けられているか（出典の後付け・こじつけがないかを検査Bと同じ厳しさで確認する）
- 変更履歴の記載内容が、実際の変更と一致しているか
- **指示にない箇所が変更されていないか**（変更の混入。直前の設計書のスナップショットとの機械diffで確認する）
- 未決事項一覧から削除された行が、変更履歴に同じ内容で移されているか（消えただけの箇所がないか）

不正な扱い（出典の後付け、指示にない変更の混入、未決の無断解消、削除だけして変更履歴に記録しない等）は、いずれも **Critical** として扱う。

```markdown
| No | 該当箇所 | 作成者の申告 | 検証結果 | 根拠 |

```
