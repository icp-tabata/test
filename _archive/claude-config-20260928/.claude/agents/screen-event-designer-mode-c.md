# screen-event-designer モードC（設計変更）詳細規則

`screen-event-designer` がモードC（設計変更）として呼び出された場合にのみ適用される規則。呼び出し元から本ファイルのパスが提示されたら、着手前に必ず Read すること。本体（`screen-event-designer.md`）のモードA・Bの内容とは独立しており、モードA・Bの呼び出しではこのファイルは不要（Readしない）。

## 規則

既存の設計書に対し、レビュー指摘とは異なる理由（要件・モックアップ・hld設計書の更新、未決事項の解消、ユーザーからの直接の変更依頼）による修正を行う。以下を厳守する。

1. **呼び出し元から提示された「変更内容の指示」に基づく箇所のみを直す。指示されていない箇所は変更しない。** 気になる箇所を見つけても、指示外であれば直さず、報告の「呼び出し元への申し送り」に書く。
2. **未決事項への回答を書いてよいのは、呼び出し元が新しい出典（更新された要件・hld設計書・確定した参照資料等）を明示的に提示した場合に限る。** 出典の提示なしに「決めてほしい」とだけ依頼された場合、それは仕様決定の依頼でありあなたの役割ではない。未決のまま維持し、その旨を報告する。
3. **解消した未決事項は、未決事項一覧から削除し、「変更履歴」（本体の出力書式を参照）に移す。** 削除するだけで記録が失われないよう、必ず変更履歴に同じ内容を追記する。
4. **未決事項の解消以外の変更（新機能の追加・記述の訂正等）も、変更履歴に記録する。**
5. **修正した箇所は、設計書本文にコメントを残さず、「変更履歴」表の該当行で示す。** 変更履歴の「該当箇所」欄は、一意に特定できる粒度で書く。
6. **「変更内容一覧」を報告に必ず含める。** 呼び出し元から提示された変更指示の全項目について、`反映` / `未決のまま維持`（出典が無かった） / `対象外`（該当箇所が存在しない等）のいずれかと、その根拠を書く。この表を省略してはならない。

## 自己点検（本体の手順4に追加）

- [ ] 変更内容の指示の全項目について、変更履歴に `反映` / `未決のまま維持` / `対象外` のいずれかを記載した
- [ ] **指示されていない箇所を変更していない。** 呼び出し元から提示された「直前の設計書のスナップショット」との機械的な差分（`Bash` の `diff` 等）を取り、変更履歴Noに紐づかない差分が無いことを確認する
- [ ] 未決事項を解消した箇所はすべて、呼び出し元が提示した新しい出典で裏付けられている（出典なしに解消した箇所がない）
- [ ] 解消した未決事項は未決事項一覧から削除され、変更履歴に同じ内容で記録されている（消えただけの箇所がない）
- [ ] 出典の提示なしに「決めてほしい」とだけ依頼された未決事項は、解消せず維持した

## 報告書式（本体の報告書式に追加する節）

```markdown
### 変更内容一覧（設計変更の場合のみ）

| No | 該当箇所 | 反映状況 | 出典 | 説明 |
| --- | --- | --- | --- | --- |
| 1 | 未決No.7 | 反映 | hld/画面一覧.xlsx | 遷移先が確定したため記載し、未決一覧から変更履歴へ移動 |
| 2 | メニュー追加依頼 | 対象外 | - | モックアップ・要件のいずれにも存在しない機能のため、未決として新規登録した |
```
