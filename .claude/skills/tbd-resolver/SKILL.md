# TBD の解消（設計書 Excel の写しの赤字修正）

不明点一覧の TBD をもとに、基本設計書（Excel）の**写し**を1件ずつ修正する。原本は読むだけで、書き込まない。原本への反映は、修正前後の記録をもとにユーザーが `scripts/excel-apply.ps1` を実行して行う。
方針の正は `docs/design/README.md` 1章。本スキルはその手順である。

## 守ること（理由つき）

- **書き込むのは写しと、修正前後の記録ファイル（`edits/*.json`。スクリプトが書く）だけ。** 原本・不明点一覧・md の設計書・その他のファイルは編集しない。原本は基本設計の参照フォルダ（プロジェクト外。人と共有）にあり、誤って直すと元に戻せないため。フックでは縛らない方針なので、この規則と下のスクリプトの検査で守る。
- **書き込みは `scripts/excel-copy.ps1` だけで行う。** openpyxl 等で保存し直すと、描画部品・画像・印刷設定が消えるファイルがある（05 DB設計書で確認）。スクリプトは Excel そのもの（COM）で開いて保存し、書き込み先が `docs/design/(screens|batches)/<ID>/*.xlsx` でなければ止まる。読み取りは openpyxl でもよい。
- **1件ずつ承認を得る。** TBD 1件ごと（1件が複数の Excel にまたがる場合は Excel ごと）に修正案を Plan Mode で示し、承認を得てから書き込む。まとめて修正しない。設計書は人の判断が要る記述が多く、一括にすると誤りに気づけないため。
- **推測で埋めない。** 修正後の値は、ユーザーの回答か、出典にある記述だけから作る。回答が無ければ聞く。
- **`excel-apply.ps1` は実行しない。** 原本（人と共有。基本設計の参照フォルダ）への書き込みは、CLAUDE.md の絶対禁止（ワークスペース外への書き込み）の趣旨に反するため、ユーザーだけが自分のターミナルで実行する。`.claude/settings.json` の deny で実行を拒否し、スクリプトも `CLAUDECODE` 環境変数がある場合と、入力が端末でない場合に止まる。Claude Code は実行のコマンドを案内するだけにする。deny や検査を回避して実行しない。
- **写しのバックアップは取らない。** 写しが壊れたら原本から作り直せる。原本のバックアップは `excel-apply.ps1` が反映の前に取る（`docs/design/_backup/`。git には載せない）。

## 入力

| 指定 | 必須 | 省略したとき |
|---|---|---|
| 画面ID／バッチID | 必須 | 聞き返す（推測しない） |
| TBD番号 | 任意 | 不明点一覧の「未解消」を上から1件ずつ進める |
| 回答（直す内容） | 任意 | TBD の「確認したいこと」を示して回答をもらう |

## 手順

### 1. 準備

1. 対象の種別を決める。画面ID（`U-…`・`O-…` 等）は `screens`、バッチID（`B-…`）は `batches`。
2. 成果物フォルダ `docs/design/<種別>/<ID>/` と、不明点一覧 `<ID>_unknowns.md` を確かめる。無ければ止めて報告する。
3. 基本設計の参照フォルダ（原本の場所）を `CLAUDE.local.md` から読む。書かれていなければ止めて聞く。
4. 現在のブランチが `design/<ID>` かを `git branch --show-current` で確かめる。違えば止めて、切り替えるかを聞く（写しはこのブランチに載せる。README 1章）。

### 2. 反映済みの TBD を知る

成果物フォルダにある写し（`*.xlsx`）ごとに、変更履歴を読む。

```powershell
& .claude/skills/tbd-resolver/scripts/excel-copy.ps1 -Mode list-history -Path <写し>
```

内容の先頭が `【<ID> TBD-番号】` の行がある TBD は、その Excel へは反映済みとして扱う。不明点一覧の「状態」は書き換えない（不明点一覧は designer の成果物で、解消への更新は md の置き換えとあわせてオーケストレーターの change モードで行うため）。

### 3. TBD を1件選んで示す

TBD の指定が無ければ、「未解消」かつ反映済みでないものを上から1件選ぶ。ユーザーに次を示す。

- TBD 番号・見出し・根拠・確認したいこと
- 修正する Excel・シート・セルの候補（TBD の「根拠」に書かれたファイル名・シート名・セル番地・行番号から割り出す）と、その原本の現在の値（`-Mode read` で読む）。根拠の箇所が実在しない、または引用と原本の値が違う場合は、推測で別のセルを選ばず、その旨を示してユーザーに聞く。「根拠」がファイル名の略称やシート名不明の古い形式の不明点一覧は、原本を検索して箇所を特定し、特定した箇所をユーザーに示して確認を取る
- 回答が無ければ、回答を求める

次の場合は Excel を直さずに、理由を示して「飛ばしてよいか」を聞く。

- 回答が md 側だけで済む（Excel に書き足すことが無い）
- 対象の Excel が範囲外：変更履歴シートの無いファイル（`00_設計書一覧`・`99_2次開発以降対応一覧`・`別紙_決済パラメータ設計書`）。何もしない
- 決定済みの方針で片づく：例えば Excel 内の Figma の記述は無視する決定があり、Figma を正とする記述は直す対象にしない

ユーザーが「スキップ」と言えば次の TBD へ、「ここまで」と言えば 7 へ進む。

### 4. 修正案を Plan Mode で示す

Plan Mode に入り（EnterPlanMode）、次を表にした修正案を示して、ExitPlanMode で承認を求める。

| 項目 | 内容 |
|---|---|
| TBD | `<ID> TBD-番号` |
| 写し | `docs/design/<種別>/<ID>/<ファイル名>`（無ければ新規に作成すると書く） |
| シート・セル | 例：`API定義`!D200 |
| 修正前 | 原本（写しがあれば写し）の現在の値 |
| 修正後 | セルの値の全体 |
| 赤字にする部分 | 追記・置換した部分だけ（`-RedText`）か、セル全体か |
| 変更履歴の内容 | `【<ID> TBD-番号】<何をどう直したか>` |

- 1件で複数のセルを直す場合は、行を並べて1つの案にする。複数の Excel にまたがる場合は、Excel ごとに案を分けて1つずつ承認を得る。
- 行を挿入しないと書けない場合（表の途中に行を足す等）は、スクリプトでは扱えない。案を出さずに止めて、ユーザーに相談する。
- 修正するセルが写しで既に一部赤字になっている場合、値を書き換えると以前の赤字が消える。案にその旨を書く。

承認されなければ、指摘に沿って案を直して出し直す。承認の範囲は、その案に書いたセルと変更履歴の行だけである。

### 5. 写しを修正する

写しが無ければ、原本から作る（原本は読むだけ）。

```powershell
& .claude/skills/tbd-resolver/scripts/excel-copy.ps1 -Mode copy -Source <原本> -Kind <screens|batches> -Id <ID>
```

承認した案のセルを書き換える。変更箇所は赤字（FF0000）になる。

```powershell
& .claude/skills/tbd-resolver/scripts/excel-copy.ps1 -Mode edit -Path <写し> -Tbd TBD-番号 -Sheet <シート名> -Cell <セル> -Value '<修正後の値の全体>' [-RedText '<赤字にする部分>']
```

`edit` と `history` は、修正前後の値を記録ファイル `docs/design/<種別>/<ID>/edits/<ブック名>.json` に追記する（`history` の `-Content` は `【<ID> TBD-番号】` で始める）。記録は原本への反映の入力になるので、手で編集しない。同じセルを同じ TBD で直し直した場合、修正前は最初の値のまま残る。

スクリプトが止める場合（いずれも、理由を示してユーザーに相談する）:
- 数式のセル、範囲、値が数式になるもの（`=` `+` `-` で始まる値等）は修正できない。
- `-RedText` が値の複数箇所に含まれる場合は、位置が決まる語に直す。
- `history` は TBD ごとに 1回だけ。追記済みの TBD へは再実行できない。
- 写しを消して `copy` で作り直そうとしても、記録が残っていれば止まる。記録の修正前は古い原本の値なので、作り直すと反映できなくなる。記録を退避・削除してよいかは、ユーザーに確認する。

変更履歴に1行追記する（1件の TBD × 1つの Excel につき1行）。版・変更日・変更者（`Claude`）はスクリプトが入れる。版は写しの最初の修正で1つ上げ（1.0 → 1.1）、以降は据え置く。

```powershell
& .claude/skills/tbd-resolver/scripts/excel-copy.ps1 -Mode history -Path <写し> -Content '【<ID> TBD-番号】<内容>'
```

- 値にシングルクォートを含む場合は `''` に重ねる。改行は `` "`n" `` で渡す。
- Excel で開いたままのファイルは書き込めない（スクリプトが止まる）。閉じてもらってからやり直す。

### 6. 確かめて次へ

1. `-Mode read` で修正したセルを、`-Mode list-history` で変更履歴を読み直し、承認した案と一致するかを確かめる。
2. 原本のハッシュ（`Get-FileHash`）が、`-Mode copy` の出力の値から変わっていないことを確かめる（写しを既に持っていた場合は、この件の着手前に取った値と比べる）。
3. `git status --short` で、変わったファイルが写しと記録ファイル（`edits/*.json`）だけであることを確かめる。
4. 結果を短く報告し、3 に戻って次の TBD へ進む。

### 7. 終わりの報告

次を報告する。

- 反映した TBD（TBD 番号・Excel・シート・セル）、飛ばした TBD と理由
- 検証の結果（6 で行った確認の内容と結果）。行っていない確認があれば「未検証」と書く
- 原本への反映の案内（ユーザー向け。内部のスキル名・エージェント名は出さず、実ファイル名で埋めたコマンドを貼る）：
  - 【あなた】自分のターミナル（プロジェクトのルート）で、次のコマンドを貼って実行してください（私は実行できません）。Excel は閉じてから実行します。
    ```powershell
    .claude/skills/tbd-resolver/scripts/excel-apply.ps1 -Manifest docs/design/<種別>/<ID>/edits/<ブック名>.json [-Tbd TBD-番号]
    ```
  - 差分の一覧が出るので、よければ「反映する」と入力します。違うときは何も入力せず終了すれば、原本は変わりません。
  - 反映の前に、原本のバックアップが `docs/design/_backup/` に作られます。
  - 原本が写しを取った後に更新されていると、何も書かずに止まります。その場合は表示を私に貼ってください。
  - 【あなた】実行が終わったら、結果（出力の最後の数行）を私に貼ってください。
  - 【あなた】その後、設計書 md への反映を、次の一文で依頼してください。
    > <ID> の設計書に、解消した TBD を反映して
  - 以下は、止まったときの対処と内部の動作の説明（ユーザー向けの案内には、必要な範囲だけ使う）。
  - 最初に、原本の更新日時を、写しを取った時（`copy` が記録に残す）と比べる。更新されていれば、何も書かずに中止する（更新日時が違っても、内容が写しを取った時、または前回の反映の直後と同じなら続ける）。中止した場合は、他の人が原本を直した可能性があるので、原本の現状を確認し、写しの作り直しを Claude Code に相談する。古い形式の記録（更新日時なし）は判定できず、そのままセル単位の判定に進む。
  - TBD ごとに、原本の現在値（大文字小文字も区別）が記録の修正前と一致するセルだけを書く。「不一致」「要確認」（数式のセル、1つのセルに複数の文字色）が 1つでもある TBD、変更履歴の記録が無い TBD は、1セルも書かない。
  - 差分の一覧を出し、「反映する」の入力を求める。その後、原本を `docs/design/_backup/` に複製し、書き込み前に判定をやり直し、保存の前後に書いた値を確かめる。
  - 変更履歴は、1回の実行で版を 0.1 上げて 1行ずつ足す。変更者は `Claude(適用: <実行者>)`。
  - 反映した TBD は `edits/<ブック名>.applied.json` に残り、次からは対象にならない。人が原本を差し戻した TBD を書き直すときだけ `-Tbd TBD-番号 -Reapply` を付ける。
  - 「不一致」が出たら、原本を他の人が直した可能性がある。原本の現状を確認し、写しの作り直しは Claude Code に相談する。
- 次の作業の案内：md の `【TBD-番号】` の置き換えと不明点一覧の更新は、`screen-design-orchestrator`（バッチは `batch-design-orchestrator`）に変更として依頼する。変更内容には、反映した TBD と Excel の写しのパスを書く
- コミットはユーザーの承認を得てから行う。push はユーザーが明示的に指示したときだけ行う
