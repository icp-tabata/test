# U-LG-02 メールアドレス登録

## 1. 概要

- 新規登録の手続きにおいて、本人のメールアドレスを登録し、確認コードの送信を求める画面である（06 グループ1【本人確認の流れ】No.3）。
- 本人確認情報入力での突合により、手続きが新規登録と確定した場合に表示する。再紐付けの場合は本画面を経由しない（06 グループ1【本人確認の流れ】No.3）。
- 登録するメールアドレスは、確認コードの送信先となり、個別の通知の送信先となる（06 A105）。
- 登録したメールアドレスは、登録の完了（06 A103）まで、暗号化してワンタイムパスワードの行に保持する。プロフィールは登録の完了まで作らない（06 A105）。
- メールアドレスは2回入力させる（画面一覧 遷移図（一般）「メールアドレス登録 2回入力」）。
- メールアドレスを、パス・問い合わせ文字列に含めない（04 4.3【個人を識別する値】）。
- タブバーを表示しない（04 4.2【タブバー】）。
- 主たるボタンを画面の下端へ固定しない（04 4.2【スクロール】）。

## 5. イベント

| ID | 契機 | 対象 | API | 遷移先 |
|---|---|---|---|---|
| E01 | 初期表示時 | − | なし | − |
| E02 | ボタンの押下 | No.7 | 【TBD-001】（冪等キーを付与しない） | 確認コード入力 |

### E01 初期表示時

- 遷移元：本人確認情報入力（突合により手続きが新規登録と確定した場合。06 グループ1【突合結果の扱い】）。それ以外の遷移元（確認コード入力から戻る場合など）は【TBD-010】とする。
- 前提条件：一次トークン（手続きの種別：新規登録）を保持している（3章）。
- 処理の内容：
  1. API を呼ばない。本画面は表示の時点で取得を行わない（04 4.5【表示時のイベント】）。
  2. 本人確認情報入力から遷移した場合は、No.3・No.4 を未入力とし、No.7 を非活性として表示する（4.2）。それ以外の遷移元の場合に入力した値を残すかは【TBD-010】とする。
- 前提条件を満たさない場合：【TBD-010】
- エラー時：なし（API を呼ばないため）。

### E02 「確認コードを送信する」の押下

- 前提条件：No.7 が活性である（4.2。活性とする条件は【TBD-008】）。
- 処理の内容：
  1. 確認のダイアログを出すかは【TBD-012】とする。
  2. No.7 を非活性とし、処理中である旨を示す（04 4.9【二重送信】）。
  3. 【TBD-001】に、No.3 の値を「メールアドレス」（`email`）として送る。一次トークンを Authorization: Bearer で付与する（06 A105【認証】）。No.4 は送らない（4.1）。冪等キーは付与しない（06 6.1【冪等キー】の7つの API に含まれない）。
  4. 成功した場合は、応答の「送信先のメールアドレス（伏せ字）」（`masked_email`）・「確認コードの有効期間」（`otp_expires_in`）を保持し（3章）、確認コード入力へ遷移する。
- 前提条件を満たさない場合：操作を受け付けない（04 4.5【前提条件】）。
- エラー時：7章による。

## 6. データの読み書き

イベントが呼ぶ API による、テーブルの読み書きを示す（C：作成、R：参照、U：更新、D：削除）。

| イベント | API | テーブル | 操作 | 対象の行 | 内容 |
|---|---|---|---|---|---|
| E02 | 【TBD-001】 | ワンタイムパスワード | C | 1行（同じ加入者IDの行が既にある場合は【TBD-011】） | 加入者ID（`member_id`。一次トークンから引く）・メールアドレス（`mail_address`。暗号化）・ワンタイムパスワード（`otp`。ハッシュ）・有効期限日時（`valid_deadline_datetime`。確認コードの有効期限は10分。03 3.1【確認コードの仕様】）・登録日時（`insert_datetime`） |
| E02 | 【TBD-001】 | 監査ログ | C | 1行 | 確認コード発行（`otp_send`）。新規登録でメールアドレスを登録し、確認コードを送信したときに記録する（11 別シート「監査ログ対応表」No.5） |

- 確認コードのメールは、API の処理の中でブラストエンジンの API を呼び出して送信する。メール送信依頼の行は作成しない（13 13.7【送信の方式】、12 12.1 No.11）。
- 本画面のイベントでは、削除を行わない。
- プロフィールは作成しない。登録の完了（06 A103）のときに、ワンタイムパスワードの行に保持したアドレスをプロフィールへ移す（06 A105・A103）。
- 確認コードのメールの送信に失敗した場合（AUTH-0103）に、ワンタイムパスワードの行を残すかは【TBD-011】とする。
