# U-LG-02 メールアドレス登録

## 1. 概要

- 加入者のメールアドレスを登録する画面である。
- 利用登録の手続きのうち、新規登録の場合にのみ表示する。再紐付けの場合は本画面を経由しない（06 6.1【本人確認の流れ】）。
- 登録したメールアドレスへ確認コードを送信し、確認コード入力で検証する。検証したメールアドレスは、LINEアカウントの変更時の再紐付けの本人確認にも用いる（03 3.2【追加照合】）。
- メールアドレスは、確認のため2回入力させる（画面一覧 遷移図（一般））。
- タブバーを表示しない（04 4.2【タブバー】）。
- 主たるボタンを画面の下端へ固定しない（04 4.2【スクロール】）。

## 5. イベント

| ID | 契機 | 対象 | API | 遷移先 |
|---|---|---|---|---|
| E01 | 【TBD-018】 | − | なし | − |
| E02 | ボタンの押下 | No.7 | 【TBD-001】（冪等キーを付与しない） | 確認コード入力 |

### E01 【TBD-018】

- 遷移元：本人確認情報入力（判別した手続き（`procedure`）が新規登録（`registration`）の場合）
- 前提条件：手続きの種別が新規登録の一次トークンを保持している。
- 処理の内容：
  1. 取得を行わない（04 4.5【表示時のイベント】）。
  2. 4章の初期値により表示する。
- 前提条件を満たさない場合：【TBD-013】
- エラー時：なし（API を呼ばない）。

### E02 「確認コードを送信する」の押下

- 前提条件：No.7 が活性である。
- 処理の内容：
  1. No.3・No.4 を 4.1 の規則により検証する。誤りがある場合は、該当する入力欄の直下に示し（04 4.6【①インライン】）、API を呼ばない。
  2. No.7 を非活性とし、処理中である旨を示す（04 4.9【二重送信】）。
  3. 【TBD-001】を呼ぶ。「メールアドレス」（`email`）に No.3 の値を送る。Authorization に一次トークンを付与する（06 6.2【共通のヘッダー】）。冪等キーは付与しない（06 6.1【冪等キー】の対象外）。
  4. 成功した場合は、応答の「送信先のメールアドレスを伏せ字で示す」（`masked_email`）・「確認コードの有効期間（秒）」（`otp_expires_in`）を渡して、確認コード入力へ遷移する。
  5. エラーの応答を受け取った場合は、No.7 を 4.2 の条件により活性に戻す（04 4.9【二重送信】）。
- 前提条件を満たさない場合：操作を受け付けない（04 4.5【前提条件】）。
- エラー時：7章による。

## 6. データの読み書き

イベントが呼ぶ API による、テーブルの読み書きを示す（C：作成、R：参照、U：更新、D：削除）。

| イベント | API | テーブル | 操作 | 対象の行 | 内容 |
|---|---|---|---|---|---|
| E02 | 【TBD-001】 | ワンタイムパスワード | 【TBD-017】 | 加入者ID（`member_id`）が一次トークンの加入者である行。行を作るか既存の行を更新するか、既存の行を更新する場合にどの行を対象とするか（初回・再度の要求のそれぞれ）は【TBD-017】 | 加入者ID（`member_id`）（一次トークンから）・メールアドレス（`mail_address`）（暗号化）・ワンタイムパスワード（`otp`）（確認コードに加入者IDを含めたハッシュ）・有効期限日時（`valid_deadline_datetime`）（10分後）・登録日時（`insert_datetime`）（行を作成する場合） |
| E02 | 【TBD-001】 | 監査ログ | C | 1行 | イベント種類（`event_type`）＝確認コード発行（`otp_send`）。メールアドレスを登録し確認コードを送信したときに記録する（11 別シート「監査ログ対応表」） |

- 確認コードのメールは、【TBD-001】の処理の中でブラストエンジンの API により送信する。メール送信依頼の行は作らない（12 12.3【メール送信】）。
- プロフィールは作成しない。登録の完了（06 A103）まで作られない（06 A105）。
- ワンタイムパスワードに対して行う操作（作成・更新・削除の別、前の確認コードの扱い。初回・再度の要求のそれぞれ）は【TBD-017】
- 監査ログは追記のみとし、更新・削除を行わない（11 11.4【改ざん防止】）。
