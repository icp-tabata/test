# U-SM-06 注文確認

## 1. 概要

- カートの内容・お届け先・金額の内訳を示し、申込みを確定させる画面である。
- 特定商取引法12条の6の最終確認画面にあたる。本画面の「この内容で注文する」により申込みが確定し、売買の契約が成立する（06 グループ4）。
- 決済は、次の外部の画面（決済。ペイジェントの画面）で行う。決済の画面を中断して戻った場合、および決済が失敗して戻った場合も本画面を表示する（07 7.2）。
- 決済の画面から戻った後の申込みのやり直しは、既存の注文に対して行う（06 A406）。服用者情報は注文に保持済みのため、入力し直さない。お届け先を変更した場合は、注文へ反映してから申し込む。
- 法定の表示（No.10〜14）は、状態によって省かない。
- 主たるボタンを画面の下端へ固定しない（04 4.2【スクロール】）。

## 2. 画面イメージ

- モック：`screen-mock.html` の U-SM-06 の枠（通常）と ERR-05 の枠（決済が失敗して戻った状態）

### E01 初期表示時

- 遷移元：情報提供確認、配送情報入力（お届け先の変更から戻る）、規約表示画面（規約の表示から戻る）。決済の画面からの復帰は E02 による。
- 前提条件：3章の服用者情報・同意・情報提供の確認の結果、または注文ID（決済の画面から戻った後）を保持している。
- 処理の内容：
  1. カートの取得により、カートの内容・お届け先・金額の内訳を取得し、表示する。
  2. 「カート内の商品」（`items`）が空の場合は、カート内容確認へ遷移する。
- 前提条件を満たさない場合：カート内容確認へ遷移する。

### E02 外部の画面からの復帰（処理中断時戻りURL）

- 前提条件：ローカルストレージに、有効期限（30分）内の退避がある。
- 処理の内容：
  1. 退避を取り出し、ローカルストレージから削除する（07 7.5【セッションの保持】）。注文IDはメモリに保持する（3章）。
  2. 注文の取得により、注文の状態を取得する。注文の取得は、決済情報差分通知により記録した結果を返す（07 7.1【結果の通知】）。戻りURLの値を結果の判定に用いない（04 4.9【復帰後の表示】）。
  3. 「決済の結果」（`payment_status`）により分ける。
     - 完了（`completed`）：注文完了へ遷移する。
     - 失敗（`failed`）：No.1 で失敗を示し、No.16 を表示する。
     - 未確定（`pending`）：確認中とし、No.1 で確認中を示す。3秒の間隔で最大10回、注文の取得をやり直し、完了・失敗になればそれぞれの扱いとする（04 4.9【復帰後の表示】）。
  4. 上限を過ぎても未確定の場合は、決済を中断したものとして通常の表示とし、申込みのやり直しを受け付ける。通知が遅れていて二重に成立した場合は、運用者が取り消す（07 7.4【複数の取引】）。
  5. 完了以外の場合は、カートの取得によりカートの内容を取得し、表示する。
- 前提条件を満たさない場合：アプリを起動し直した場合と同じ扱いとする（04 4.9【復帰時のセッション】）。

### E03 「お届け先を変更する」の押下

- 前提条件：なし
- 処理の内容：3章の値を保持したまま、配送情報入力へ遷移する。

### E04 「この内容で注文する」の押下

- 前提条件：No.15 が活性である。
- 処理の内容：
  1. 冪等キー（Idempotency-Key。UUID v4）を生成する。応答を受け取れずに再送する場合は同じ値を用いる。応答を受け取った後の操作では新しく生成する（04 4.9【冪等】）。
  2. 保持している値により、呼ぶ API を分ける。
     - 注文IDを保持している場合（決済の画面から戻った後）：決済の申込みのやり直しに、注文IDを送る。服用者情報は送らない。お届け先を変更していれば、注文へ反映される（06 A406）。
     - それ以外で、3章の服用者情報・同意・情報提供の確認の結果を保持している場合：注文の確定に、これらの値を送る。
  3. 決済の申込みのやり直しの「申込みの結果」（`payment_status`）が完了（`completed`）の場合は、注文完了へ遷移する。
  4. それ以外の場合は、セッショントークン・注文ID・退避の有効期限（30分）をローカルストレージへ退避する（07 7.5【セッションの保持】）。
  5. 3章の服用者情報・同意・情報提供の確認の結果を破棄する。
  6. 応答の「決済画面のURL」（`payment_url`）へ、同じ画面の枠内で遷移する。外部のブラウザで開かない（04 4.9【外部の画面】）。
- 前提条件を満たさない場合：カート内容確認へ遷移する。
- エラー時：7章による。

### E05 「もう一度決済に進む」の押下

- 前提条件：No.16 が活性である（No.1 で決済の失敗を示している）。
- 処理の内容：E04 の処理の内容のうち、決済の申込みのやり直しを呼ぶ場合と同じとする。
- エラー時：7章による。

### E06 「カートに戻る」の押下

- 前提条件：なし
- 処理の内容：カート内容確認へ遷移する。

### E07・E08 規約へのリンクの押下

- 前提条件：なし
- 処理の内容：3章の値を保持したまま規約表示画面へ遷移し、該当する規約を選んだ状態で表示する。

- 注文の確定が決済の申込みに失敗した場合は、いずれの行も作成しない（06 A402）。
- 本画面のイベントでは、削除を行わない。更新は、決済の申込みのやり直しで注文のお届け先・送料・合計金額を改める場合に限る。
- カートを空にすること、注文の受付の確認のメールの送信の依頼を記録すること、注文の成否を監査ログに記録することは、成立の通知を受けたときに行う（06 グループ8【決済ステータスごとの処理】）。本画面のイベントでは行わない。
- 注文を作成・更新したときに注文履歴（スナップショット）の行を作るかは未定である（05 注文履歴）。

## 7. エラー時

全 API に共通するエラー（セッションの無効 AUTH-0003・レート制限の超過 COM-0100・想定しない例外 COM-0900）は、04 4.6【共通のエラー】による。本画面に固有のものを次に示す。

| イベント | API | エラー（コード） | 型 | 画面の動き | メッセージ |
|---|---|---|---|---|---|
| E01・E02 | カートの取得 | 取得の失敗 | ④画面全体 | 再度取得する操作を置く（04 4.7【失敗】） | E003 |
| E02 | 注文の取得 | 注文が存在しない、または他の会員の注文である（ORDER-0001） | ④画面全体 | カート内容確認へ遷移する操作を置く | E004 |
| E04 | 注文の確定 | お届け先が設定されていない（ORDER-0004） | ②画面内アラート | No.5 を表示する | E005 |
| E04 | 注文の確定 | カートが空である（ORDER-0002） | ④画面全体 | カート内容確認へ遷移する操作を置く | E006 |
| E04 | 注文の確定 | 同意が得られていない（OTC-0201）<br>情報提供の確認が得られていない（OTC-0300）<br>必須の項目の不足・形式の誤り（COM-0001） | ④画面全体 | 服用者情報入力へ遷移する操作を置く | E007 |
| E04 | 注文の確定 | 決済の申込みに失敗した（PAY-0001） | ②画面内アラート | 本画面に留まる。注文は作成されず、カートは保持される（06 A402） | E008 |
| E04・E05 | 決済の申込みのやり直し | 注文が存在しない、または他の会員の注文である（ORDER-0001） | ④画面全体 | カート内容確認へ遷移する操作を置く | E004 |
| E04・E05 | 決済の申込みのやり直し | 注文の状態が決済待ちではない（ORDER-0005） | ④画面全体 | カート内容確認へ遷移する操作を置く | E009 |
| E04・E05 | 決済の申込みのやり直し | 決済の申込みに失敗した（PAY-0001） | ②画面内アラート | 本画面に留まる。注文の状態は変わらない（06 A406） | E008 |
