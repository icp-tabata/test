- 実施日：2026-09-28

- 方法：サブエージェントが `docs/README.md` 全356行を読んでレビューし、行番号付きの指摘をメインセッションが本文と照合した。参考として当プロジェクトの `CLAUDE.md` を参照した
- 未確認事項：Excel 設計書（04・06・12 など）の中身は確認していない。そこで既に定められている規則があれば、該当する指摘の一部（C1・M5 など）は「md への反映方法の問題」に縮小する
- C2 の根拠の一部（外部への書き込みの禁止など）は当プロジェクトの `CLAUDE.md` による。別プロジェクトで用いる場合は、そちらの規約で読み替える

## 総評

人が書く設計書の規約としては完成度が高い。章立ての固定、「未定」「仮置き」の明示、章を省かない規則、CRUD の明記により、AI が書き手として従いやすい骨格ができている。

一方で、AI 駆動開発の規約としては致命的な穴が3つある。

1. 実装 AI が「正」の資料（Box 上の Excel）を読めない前提が考慮されていない。
2. AI が作業中に見つけた不整合を出す先がない。
3. 検証できる完了基準（受け入れ条件）がない。

このままでは、実装 AI は参照先を推測で埋めることになり、テストの根拠も持てない。

## 強み（残すべき点）

- 章立てが固定で、該当しない章も「なし」と書かせる（L96）。抜けが機械的に見つかり、AI の書き漏れを防げる。
- 「未定」「仮置き（根拠を添える）」を区別し、推測を禁じている（L62）。AI の幻覚を抑える最重要の規則である。
- 初期表示を E01 に固定し、イベントを表と節の二段で書かせる（L109、L116-122）。実装とテストの単位に直結する。
- CRUD、対象の行、「行わない操作」まで書かせる（L110）。
- 実装の方式は書かない、ただし要配慮個人情報の保持場所は書く、という線引き（L91、L103）。
- バッチでは「冪等と再実行」を独立した章にし、「抽出の条件と処理済みの記録の対応」をチェック項目にしている（L260、L351）。
- 共通の規則を繰り返さず参照で示す（L74）。md 間の食い違いを防げる。

## 問題点

### Critical（AI が誤った設計・実装をする）

#### C1. 「正」が AI から読めないのに、md には参照しか残らない（L8、L11、L74、L75、L251）

- 該当箇所：「全体に共通する規則は、Box の設計書（…Excel）を正とする。md には写さない。」「共通の規則は繰り返さない。適用する箇所で参照だけを示す」
- 問題：
  - 実装 AI の入力は md である。md には「（04 4.9【冪等】）」のような参照しかなく、規則の中身がない。たとえば冪等キーの生成と再利用、共通エラーの画面の動き、12.2〜12.4 のリトライ・多重起動・テナントである。
  - Excel が Box にあってリポジトリの外であれば、実装 AI はそれを読めない。読めたとしても、読むたびに大きな Excel を解析してコンテキストを消費する。
  - 読めなければ、AI は一般論（ありがちな実装）で埋める。これは、規約が禁じている「推測」を実装の段階で強いる構造である。
  - バッチ（L251）は、冪等・リトライ・テナント・多重起動という最も事故の起きやすい規則を丸ごと参照に任せており、影響が最も大きい。
- 修正案：1章に次を追記する。
  > md から参照する設計書の節は、実装する者（Claude Code を含む）がリポジトリ内で読める形にしておく。共通の規則（04 4.1〜4.10、06 6.1、12.2〜12.4、13.6）は、テキストの写し（例 `docs/design/_common/04_画面共通.md`）をリポジトリに置き、Excel を正、写しを従とする。写しの先頭には、写した設計書の版（更新日）を書く。md の参照は写しの節を指す。Excel を改訂した者は、同じ日に写しを更新する。

  あわせて、先頭の属性に `design_refs: { "04": "2026-09-01", "06": "..." }`（参照した設計書の版）を追加する。版が違えば、AI は md が古いと判定できる。

#### C2. AI が見つけた不整合を出す先がない（L14、L92、L354）

- 該当箇所：
  - L14「md の中で補わず、設計担当が設計書を赤字で修正する。申し送りには書かない。」
  - L92「課題や申し送りの経緯」（書かないもの）
  - L354「設計書と食い違う事柄・足りない事柄は、設計書を赤字で修正した」
- 問題：
  1. AI は Excel に赤字を入れられない。仮に入れられても、Box への書き込みは外部への書き込みになる。
  2. その結果、不整合を見つけた AI の選択肢は、「黙って md で補う（L14 違反）」か「黙って捨てる」かの2つだけになる。
  3. L354 は、AI が「修正した」と自己申告するだけの項目であり、他者が確認できない。
  4. 「申し送りに書かない」「経緯を書かない」は、人向けの情報を整理する規則としては正しい。しかし、AI から人への報告経路まで塞いでいる。
- 修正案：L14 を次に置き換える。
  > 設計書と食い違う事柄・足りない事柄を見つけた場合、md の中で補わない。該当する箇所は「未定（設計書の確認待ち：06 A406【エラー】）」と書く。Claude Code が見つけた場合は、設計書を修正せず、作業の報告に「要修正事項」として、設計書の番号・節・現状・食い違う相手・修正の案を列挙し、設計担当に渡す。設計担当が赤字で修正した後、「未定」を実際の値に置き換える。

  L354 を次に置き換える。
  > - [ ] 設計書との食い違い・不足を「未定（設計書の確認待ち：…）」と書き、要修正事項として報告した（設計書の修正は設計担当が行う）

#### C3. 受け入れ条件（検証できる完了基準）の章がない（L98-114、L253-265、両雛形）

- 問題：
  - イベント・エラー・状態は書かれているが、「何が成立したら完成か」を示す検証可能な記述がない。
  - そのため実装 AI は、テストを処理の内容から逆算して作ることになる。結果は実装に合わせたテストになり、期待値を実装に合わせるのと同じ構造になる。
  - 冪等・越境・二重送信のような「起きてはいけないこと」のテストも抜ける。
- 修正案：画面・バッチの両方に「11. 受け入れ条件」を追加する（参照は 12 章に繰り下げる）。
  > | ID | 前提 | 操作 | 期待する結果 | 対応 |
  > AC-01 のように振る。「対応」には E01・7章の行・6章の行などを書く。5章の各イベント、7章の各エラー、5章で冪等キーを付けた API には、少なくとも1つの受け入れ条件を置く。冪等キーを付けた API には「同じキーで2回送ると、2回目は1回目と同じ結果を返し、テーブルは1回分だけ変わる」形の条件を必ず置く。

  9章に「[ ] 各イベント・各エラー・冪等の API に、受け入れ条件がある」を追加する。

#### C4. 「未定」「仮置き」を実装側でどう扱うかが決まっていない（L62、L100、L132）

- 問題：
  - 書き手には推測を禁じているが、読み手（実装 AI）がどう扱うかが決まっていない。
  - 本文に散らばった「未定」は見落とされ、ありがちな値で実装される。
  - 「仮置き」（例：全国一律550円）はハードコードされ、確定した後も残る。
- 修正案：4.1 に次を追記する。
  > 「未定」「仮置き」は、本文に書くとともに、先頭の属性 `open_items` に列挙する（例 `- 仮置き: 送料 550円（06 グループ3【本グループの前提】）`）。未定の事柄を含むイベントは実装しない。仮置きの値は設定値として外に出し、コードに直接書かない。

  9章に「[ ] 本文の『未定』『仮置き』がすべて `open_items` に載っている」を追加する（grep で機械的に照合できる）。

## Claude Code での置き方

本書は、性質の違う4つのものを1ファイルにまとめている。規則（4章）、雛形（6・8章）、確認（9章）、人の運用（1章の相談の表）である。次のように分けると、必要なときに必要な分だけ読ませられる。

| 内容 | 置き場所 |
| --- | --- |
| 規則と雛形の所在 | スキル（例 `.claude/skills/event-design/SKILL.md`）。description に「画面・バッチのイベント設計 md を書く・直すとき」と発動条件を書く |
| 雛形 | スキル配下の `templates/screen.md`・`templates/batch.md`。コピーして使わせれば、章の抜けがなくなる |
| 9.1 の機械で確かめる項目 | スクリプト（先頭の属性と本文の突き合わせ） |
| 9.2 の判断する項目 | レビュー用のサブエージェント（例 `.claude/agents/design-reviewer.md`）。書いた AI とは別の文脈で確かめさせる |
| 設計の正の分担（Excel が正、md は従、写しの場所） | CLAUDE.md に1行だけ書く（スキルの一覧は書かない） |
| 1章の「相談の要否」 | 人の運用なので AI 向けのスキルからは外し、「Claude Code は設計書を修正しない」の一文に置き換える |

## 優先して直すべき上位3件
